이번 턴에는 **코드를 수정하지 마라.** 읽고 보고만 한다.

다음 순서로 읽어라. 필요한 것만 읽고, 큰 문서는 해당 절만 읽어라.

1. `.claude/rules/00-source-of-truth.md`
2. `README.md`
3. `docs/00-project/STATUS.md`
4. STATUS.md가 가리키는 **활성 SPEC**의 `spec.md` + `acceptance.md`
5. 그 SPEC이 참조하는 ADR / `docs/api.md` / `docs/model.md`의 **해당 절만**

읽은 뒤 다음 7가지를 보고하라. 각 항목은 3줄을 넘기지 마라.

1. **현재 프로젝트의 목적** — 한 문장
2. **현재 작업 중인 SPEC** — ID와 범위(엔드포인트 번호 포함)
3. **해당 SPEC의 완료 조건** — `acceptance.md`에서, 몇 개 중 몇 개가 체크됐는지
4. **관련 Architecture Decision** — 이 SPEC을 구속하는 ADR 번호와 그 내용 한 줄씩
5. **현재 구현 상태** — 실제 파일을 확인하고 답하라. 문서가 주장하는 상태가 아니라 **코드의 실제 상태**
6. **불확실하거나 서로 충돌하는 내용** — 없으면 "없음". 있으면 어느 문서끼리 충돌하는지 표로
7. **다음으로 수행할 최소 작업 단위** — TASK ID 하나. 왜 이것이 다음인지 한 줄

마지막에 이렇게 물어라: "이대로 진행할까요, 아니면 다른 것부터 볼까요?"

Owner 확인 전에는 구현을 시작하지 마라.
