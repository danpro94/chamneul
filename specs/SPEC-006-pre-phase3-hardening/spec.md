## 1. 배경 — 왜 Phase 3 전에 이 넷인가

API는 47/47 완료다(PR #12). 남은 것은 기능이 아니라 **앱이 localhost를 떠나는 순간 처음 깨지는 것들**이다.

| # | 지금 상태 | localhost를 떠나면 |
| --- | --- | --- |
| ① 요청 횟수 제한 | 없음 | 로그인 비밀번호 대입, 가입 API로 가입 여부 대량 조회(I-6), 재설정 메일 폭탄이 **무제한** |
| ② 운영 경로 | gunicorn + prod 설정 조합을 **한 번도 띄운 적 없음** | 정적파일 404(Admin CSS 깨짐), 헬스체크가 HTTPS 리다이렉트(301)·Host 검증(400)에 걸림, 설정을 빠뜨리면 개발 설정으로 기동(S-3) |
| ③ readiness | `/healthz`는 DB를 보지 않음 | k8s가 DB 장애 중인 파드에도 트래픽을 보낸다 |
| ④ 스모크 | 여정 12단계에 #45~#47 없음 | 새 기능 3개가 실환경 여정으로 검증된 적 없음 |

코드를 읽다 확인한 **추가 위험 2건**도 이 SPEC에서 닫는다.

* **DRF가 클라이언트 IP를 `X-Forwarded-For` 그대로 쓴다.** `NUM_PROXIES` 미설정 시 `get_ident()`는 요청자가 보낸 XFF 문자열 전체를 식별자로 쓴다(DRF 3.18.2 `throttling.py`). 공격자가 요청마다 XFF를 바꾸면 **매번 새 IP로 취급**되어 IP 기준 제한이 무력화된다.
* **캐시가 프로세스마다 따로다.** `CACHES` 미설정 = Django 기본 `LocMemCache`. gunicorn 워커 3개 × 파드 N개면 **제한이 3N배**로 풀린다.

## 3. 핵심 규칙

| 규칙 | 근거 |
| --- | --- |
| 429 응답은 **계정 존재 여부와 무관하게 동일**하다. 재설정 요청의 이메일 기준 제한은 **입력한 주소 문자열**(정규화 후)로 센다 — 가입 여부를 조회하지 않는다 | ADR-008 §2 |
| 이메일 기준 카운터 키는 **해시**로 저장한다 — 캐시 테이블에 주소 원문을 남기지 않는다 | CLAUDE.md §10 |
| 이메일 정규화는 `UserManager.canonical_email()` 하나 — 대소문자를 바꿔 제한을 우회할 수 없다 | SPEC-005 L-1 |
| 카운터는 **모든 워커·파드가 공유**하는 저장소에 둔다 | §1 |
| 클라이언트 IP는 **신뢰하는 프록시 수**(`NUM_PROXIES`)로만 계산한다. 로컬 0, 운영은 배포 구성에 맞춰 환경변수로 | §1 |
| 429에는 `Retry-After`가 붙고 본문은 api.md §1.5 봉투(`RATE_LIMITED`)다 | api.md §1.5 |
| **liveness(`/healthz`)는 DB를 보지 않는다** — DB 장애로 모든 파드가 재시작되는 연쇄를 막는다 | k8s 관행, 기존 `config/health.py` 주석 |
| readiness는 DB 연결을 확인하고 실패 시 **503**. 응답에 예외 내용을 싣지 않는다 | CLAUDE.md §8 |
| 헬스 엔드포인트 2개는 **HTTPS 리다이렉트와 Host 검증보다 먼저** 응답한다 — kubelet·ALB는 파드 IP를 Host로 HTTP 호출한다 | 운영 관행 |
| prod 설정은 콘솔 메일 백엔드·`http://` 재설정 URL이면 **기동을 거부**한다 | S-3, S-6 |

## 4. GIVEN/WHEN/THEN (요약)

### ① 요청 횟수 제한
* GIVEN 같은 IP에서 한도를 넘는 로그인 / THEN 429 + `Retry-After`, 한도 안의 요청은 영향 없음
* GIVEN 여러 IP에서 **같은 계정**으로 한도를 넘는 로그인 / THEN 429 (계정 표적 공격)
* GIVEN 요청마다 다른 `X-Forwarded-For` / THEN 여전히 같은 IP로 세어 429 (우회 불가)
* GIVEN 가입된 주소와 가입되지 않은 주소로 #45 한도 초과 / THEN **바이트 동일한 429**
* GIVEN 대소문자만 바꾼 주소로 #45 반복 / THEN 같은 카운터로 센다
* GIVEN 다른 엔드포인트(#7 등) / THEN 이번 제한의 영향 없음

### ② 운영 경로
* GIVEN prod 설정 + 콘솔 메일 백엔드 / THEN 기동 실패(`ImproperlyConfigured`)
* GIVEN prod 설정 + `http://` 재설정 URL / THEN 기동 실패
* GIVEN `DJANGO_SETTINGS_MODULE` 미지정 + wsgi 진입 / THEN (결정 4에 따라) prod로 기동 시도 → 시크릿 없으면 즉시 실패
* GIVEN 실제 이미지(gunicorn) + prod 설정 / THEN 파드 IP Host·HTTP로 `/healthz` **200**(301·400 아님), Admin CSS **200**, `X-Forwarded-Proto: https`로 API 정상

### ③ readiness
* GIVEN DB 정상 / THEN readiness 200 `{"status": "ok", "checks": {"database": "ok"}}`
* GIVEN DB 정지 / THEN readiness **503**, `/healthz`는 여전히 **200**
* GIVEN DB 오류 / THEN 응답 본문에 예외 문자열·호스트명 없음

### ④ 스모크
* 여정 12단계 + **13 재설정 요청→콘솔 링크→확정→새 비밀번호 로그인 / 14 고민 수정(배정 전 200, 배정 후 409) / 15 로그인 한도 초과 429**
* 빈 볼륨에서 전 단계 통과

## 5. Non-Goals

* **Redis/ElastiCache** — 결정 1에서 고르지 않으면 Phase 3. 지금은 인프라 추가 없이 공유 카운터를 만든다.
* **계정 잠금(N회 실패 시 잠금)** — 공격자가 남의 계정을 일부러 잠글 수 있다(서비스 거부). 잠금 대신 **속도 제한**을 쓴다.
* **CAPTCHA·WAF** — 프론트·AWS WAF가 생기는 Phase 3.
* CI, k8s 매니페스트, Dockerfile·compose 수정 — Owner 영역. 운영 경로 검증은 **compose를 고치지 않고** 빌드된 이미지를 `docker run`으로 띄운다.
* 비동기 메일 발송 — Phase 3.

## 6. 의존성

* DRF 내장 throttling — **패키지 추가 없음**.
* 결정 1(a) `DatabaseCache` — Django 내장. 캐시 테이블은 `manage.py createcachetable`(마이그레이션 아님)로 만든다 → 배포 절차(smoke-test §2-1)에 한 줄 추가. 테스트 러너는 테스트 DB에 자동으로 만든다.
* 결정 3(a) WhiteNoise — **서드파티 패키지 1개 추가 → §16 승인 대상**.
* 결정 5(a) readiness 엔드포인트 — **CLAUDE.md §7("`/healthz`만 버전 없음")·§5(엔드포인트 47개)와 충돌 → ADR-010이 먼저**(ADR-007의 교훈: SPEC 결정이 CLAUDE.md 조항과 어긋나면 결정 시점에 ADR).

| 엔드포인트 | 기준 | 한도 | 이유 |
| --- | --- | --- | --- |

## 8. 리스크

| # | 리스크 | 대응 |
| --- | --- | --- |
| 1 | **기존 테스트가 한도에 걸린다** — 한 테스트 안에서 로그인·재설정 요청을 여러 번 하는 테스트가 있다(#45 이메일당 3회) | 제한 테스트 외에는 한도를 높게 두는 테스트 설정. DRF는 `THROTTLE_RATES`를 **클래스 속성으로 import 시점에 고정**해 `override_settings`가 먹지 않는다 — 한도를 호출 시점에 읽는 스로틀 클래스로 만든다 |
| 2 | `DatabaseCache`는 요청마다 DB 왕복이 1~2회 늘어난다 | 대상이 인증 엔드포인트 4개뿐이다. 측정해서 리뷰 노트에 남긴다 |
| 3 | 헬스 엔드포인트가 Host 검증을 건너뛴다 | 데이터가 없는 GET 2개로만 한정하고, 경로를 **정확히 일치**로 판정한다(테스트로 고정) |
| 4 | 운영 경로 기동에 실제 시크릿이 필요하다 | 이미지에 굽지 않고 `docker run --env-file .env` + 일회용 `DJANGO_SECRET_KEY`. 명령 출력에 값이 찍히지 않게 한다 |
| 5 | 빈 볼륨 재기동은 로컬 데이터를 지운다 | 결정 6(a): 백업 먼저, 저장소 밖 경로, 복원 절차는 smoke-test §6 |
