# SPEC-005 — acceptance criteria

TEST_CRITERIA.md §2·§3을 SPEC-005에 적용한 판정 기준. 전항 Django 테스트로 자동 판정한다.

## AC-1. 회귀 기반 — 인증 (TASK-001)

- [ ] `#2` 가입 → 201, `sessionid` 쿠키 발급(HttpOnly)
- [ ] `#2` 응답 필드 집합이 고정돼 있다 (비밀번호·해시가 실리지 않는다)
- [ ] `#2` 중복 이메일 → 409 / 중복 닉네임 → 409 / 약한 비밀번호 → 400
- [ ] `#3` 로그인 성공 → 200 + 세션 발급
- [ ] `#3` **틀린 비밀번호와 없는 계정이 같은 응답** — 어느 쪽인지 구분되면 계정 조회 도구가 된다
- [ ] `#4` 로그아웃 → 200 + **`Session` 레코드가 실제로 삭제**됨
- [ ] `#4` 이후 같은 쿠키로 `/users/me` → 401
- [ ] `#7` 조회 필드 집합 고정 / `#8` 부분 수정 동작 / `#8` 닉네임 중복 → 409
- [ ] `#9` `roles`·`active_role`·`advisor_status` 3필드
- [ ] **구현 파일이 변경되지 않았다** (`accounts/{views,services,serializers}.py`)

## AC-2. 회귀 기반 — OAuth (TASK-002)

- [ ] `#5` 리다이렉트 URL에 `client_id`·`redirect_uri`·`state` 포함
- [ ] `#6` 신규 사용자 생성 + 닉네임 자동 산정(C-11)
- [ ] `#6` 닉네임 충돌 시 접미사 부여
- [ ] `#6` 같은 이메일의 기존 로컬 계정에 연결
- [ ] `#6` 이미 다른 Google 계정과 연결된 계정 → **409**
- [ ] `aud` 불일치 → 거부
- [ ] **mock이 `urlopen`에 걸려 있다** — 우리 파싱·분기 코드가 실제로 실행된다
- [ ] 테스트가 네트워크에 의존하지 않는다 (오프라인에서 통과)
- [ ] 구현 파일 변경 없음

## AC-3. 재설정 요청 (#45, TASK-003)

- [x] 가입된 이메일 → 200, `mail.outbox` 길이 1
- [x] **가입되지 않은 이메일 → 200, `response.content`가 가입된 경우와 동일**, `mail.outbox` 길이 0
- [x] 두 경우의 **상태 코드가 같다**
- [x] Google 전용 계정 → 200, 메일 발송되나 **본문이 로컬 계정과 다르다**
- [x] 메일 본문에 `PASSWORD_RESET_URL` 기반 링크와 `uid`·`token`이 들어 있다
- [x] 이메일 형식 오류 → 400
- [x] CSRF 토큰 없이 호출 → 403
- [x] 토큰이 DB에 저장되지 않는다 (마이그레이션 없음으로 확인)

## AC-5. 고민 수정 (#47, TASK-005)

- [ ] `SUBMITTED` + 본인 → 200, 보낸 필드가 갱신됨
- [ ] 부분 전송 시 **보내지 않은 필드는 불변**
- [ ] `ASSIGNED` → 409 / `ANSWERED` → 409 / `CLOSED` → 409
- [ ] 409인 경우 **어느 필드도 바뀌지 않았다**
- [ ] 타인의 고민 → 404 (403 아님, §1.8)
- [ ] 소프트 삭제된 고민 → 404
- [ ] 비로그인 → 401
- [ ] `status`·`author`·`deleted_at`을 섞어 보내면 200이되 그 필드는 **무시**
- [ ] 발행 SQL에 `FOR UPDATE OF "concerns_concern"`이 있다
- [ ] `UPDATE`가 **보낸 필드 + `updated_at`만** 싣는다

> **이 SPEC의 절반은 "이미 되는 것"을 고정하는 일이다.** 새 기능보다 지루하지만, #46이 로그인·세션을 직접 건드리므로 **그 동작을 지키는 테스트 없이 건드리는 것은 눈 감고 수술하는 것**이다. 그리고 OAuth는 이 프로젝트에서 자동 테스트도 스모크도 없는 유일한 영역이었다.
