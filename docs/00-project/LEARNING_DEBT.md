## 2. 최우선 2건이 왜 M4를 차단하는가

M2 퀴즈 **42/100**. ④는 **2회 연속 오답**이었다. `docs/reviews/02-milestone2-review.md`가 "M4 착수 전 재퀴즈 필수"로 못박았다.

두 항목 모두 M4의 첫 코드에서 곧바로 실물이 된다.

| 부채 | SPEC-001에서 어떻게 실물이 되는가 |
| --- | --- |
| ④ 401/403/409 | 권한 클래스가 이 판정 자체다. **인증 없음 = 401**, **인증됨 + 역할 불일치 = 403**, **중복 가입 = 409**. ADVISOR 역할을 보유했으나 `active_role`이 `USER`인 사용자가 조언가 리소스에 접근하면 403이지 401이 아니다 — 이 한 줄이 부채 ④의 전부다 |
| ⑤ atomic | 회원가입은 User 생성 + 세션 생성이 함께 성공하거나 함께 실패해야 한다. 서비스 레이어의 `transaction.atomic` 패턴을 여기서 세우고, SPEC-009의 조언가 승인 부수효과(UserRole + RoleGrant + Notification 3중 쓰기)가 그대로 재사용한다 |

**따라서 재퀴즈를 별도 이벤트로 잡지 않는다.** SPEC-001의 테스트가 두 항목을 실행 가능한 형태로 고정하고, `handoff.md`의 이해 확인 질문이 설명 가능성을 검증한다. 부채를 커리큘럼으로 전환하는 것이다.

## 4. 항목을 추가·해소하는 방법

**추가**: 퀴즈·리뷰에서 설명하지 못했거나, `handoff.md`의 "아직 설명 못 하는 것"에 적힌 항목을 §1 표에 행으로 추가한다. 등록 시점(마일스톤 또는 SPEC ID)을 반드시 남긴다.

**해소**: 다음 중 하나가 있어야 한다. 자기 신고는 해소가 아니다.

* 해당 개념을 강제하는 **통과한 테스트** (파일:테스트명)
* 재퀴즈 통과 기록 (`specs/*/evidence/`)
* 드릴 이수 기록
* 백지 재현 채점 통과

해소되면 상태를 `✅ 해소`로 바꾸고 근거 열에 경로를 적는다. **행을 지우지 않는다** — 언제 무엇으로 해소됐는지가 기록의 가치다.
