## 1. 이 앱은 무엇인가 — 사용자 눈높이 소개

> **참눌(chamneul)은, 인생의 중요한 갈림길에서 혼자 결정하기 어려울 때 믿을 만한 사람에게 조언을 구하는 곳입니다.**

**고민을 가진 사람**은 "이직을 할까 남을까", "번아웃이 왔는데 쉬어야 하나" 같은 **한 번뿐인 결정**을 씁니다. 검색해도 안 나오고, 친구에게 묻기엔 이해관계가 얽히는 종류의 문제입니다. 글을 올리면 **공개 게시판에 뜨지 않습니다.** 관리자가 그 고민에 어울리는 조언가를 **직접 연결**해주고, 그 조언가만 내용을 봅니다.

**조언가**는 아무나 될 수 없습니다. 신청서를 내고 관리자 심사를 통과해야 합니다. 신청서에는 실명도, "저는 전문가입니다" 같은 자기 평가도 적지 않습니다 — 검증할 수 없는 자기 주장은 신뢰를 오히려 깎기 때문입니다. 대신 **어떤 경험을 했는지, 그 경험으로 어떤 조언을 할 수 있는지**를 서술합니다.

조언은 바로 전달되지 않습니다. **관리자가 먼저 읽고 승인해야** 고민 작성자에게 보입니다. 반려되면 조언가에게만 사유와 함께 알림이 갑니다. 이 한 단계 때문에 "성의 없는 답변"이나 "위험한 조언"이 사용자에게 직접 닿지 않습니다.

조언을 받은 사람은 **피드백**을 남깁니다. 지금은 평가 기록일 뿐이지만, 나중에 "이 조언가의 조언이 실제로 도움이 됐는가"를 쌓아가는 재료입니다.

**한 문장으로**: 공개 Q&A가 아니라, **심사된 조언가 · 검수된 조언 · 비공개 1:1 연결**로 인생의 큰 결정을 돕는 서비스입니다.

**한 사람이 두 역할을 겸할 수 있습니다.** 조언가도 자기 고민을 올릴 수 있고, 화면 위에서 "지금은 사용자로" / "지금은 조언가로" 모드를 바꿔 씁니다.

### 사용자가 지나가는 길

```
[고민을 가진 사람]                  [관리자]                    [조언가]

  회원가입 · 로그인
        │
  고민 작성 ─────────────────▶ 고민 목록에서 확인
        │                          │
        │                     조언가 배정 ──────────▶ "고민이 배정되었습니다"
        │                          │                       │
        │                          │                   고민 상세 열람
        │                          │                       │
        │                          │                   조언 작성 · 제출
        │                          │                       │
        │                     조언 검수 ◀────────────────────┘
        │                     ├─ 승인 ──▶ "조언이 도착했습니다"
        │                     └─ 반려 ─────────────────▶ "반려되었습니다(사유)"
        │                                                   │
  조언 열람                                             수정 또는 삭제 후 재작성
        │
  피드백 작성 ───────────────▶ 피드백 확인
```

## 2. 초기 설계와 달라진 것 (Drift)

44개 API를 다 만들고 나서 보니, **설계 의도는 그대로인데 구현 중에 판단이 추가된 지점**이 여럿 있었다. 방향이 바뀐 것은 하나도 없다. 다만 두 갈래로 갈린다.

### 2-1. 더 좋아진 것 — 원래 설계보다 나아진 판단

| | 무엇이 | 왜 나아졌나 | 근거 |
| --- | --- | --- | --- |
| **조언 수정 횟수 세는 법** | 원래: "고치면 무조건 +1" → 지금: **"내용이 바뀔 때만 +1"** | 원래대로면 "저장만 눌렀다 말았다"도 수정 이력에 쌓인다. 조언가가 자기 이력을 보는 화면이 의미 없는 숫자로 채워진다 | [ADR-007](../adr/ADR-007-advice-version-counts-body-revisions.md) |
| **반려된 조언을 지울 수 있게** | 원래: 반려되면 수정도 삭제도 불가 | 원래대로면 **조언가에게 출구가 없다** — "반려됐습니다"라는 알림만 받고 아무것도 못 한다. 지울 수 있게 하니 새로 쓸 수 있는 길이 생긴다 | api.md #30 (2026-09-13) |
| **알림에 관리자 이름을 안 보여줌** | 원래 명세: 누가 처리했는지 표시 | 지금 알림 5종이 전부 관리자 행위라, 그대로 두면 일반 사용자가 **관리자 계정을 식별**하게 된다. "관리자가 승인했습니다"에 누구인지는 필요 없다 | SPEC-003 §7 결정 1 |
| **남의 알림은 "없다"고 답함** | 원래: "권한 없음" | "권한 없음"은 **그 알림이 존재한다는 사실**을 알려준다. *"알림은 나에게만"* 이라는 Owner 원칙대로, 존재 자체를 숨긴다 | SPEC-003 §7 결정 2 |
| **조언가 자격을 뺏으면 즉시 활동 차단** | 원래 명세엔 없던 연결 | 자격만 뺏고 "조언가 모드"를 그대로 두면 **자격 없는 사람이 계속 남의 고민을 본다** | 점검 A-3 (2026-09-14) |
| **잘못된 검색 조건은 거절** | 원래: 조용히 무시 | "안 읽은 것만 보여줘"라고 했는데 오타가 나면 **읽은 것까지 전부** 보여주고 있었다. 사용자가 잘못 본 목록으로 판단하게 된다 | 리뷰 AR-02 (2026-09-16) |
| **알림에 고민 내용을 복사하지 않음** | 원래: 고민 요약을 알림에 복사 | 사본은 **원본이 지워져도 남는다.** 사용자가 고민을 삭제해도 전 조언가 알림함엔 그대로 있었다. 지금은 알림엔 "확인하세요"만 있고 내용은 그때그때 원본에서 가져온다 | 리뷰 S-2·AR-08 (2026-09-16) |
| **자격 회수돼도 다시 신청 가능** | 원래: 한 번 승인되면 영영 재신청 불가 | 회수 기능이 생기면서 **막다른 길**이 만들어졌다 — 자격을 잃었는데 다시 신청도 못 하고, 취소할 방법도 없었다 | 리뷰 AR-01 (2026-09-16) |

### 2-2. 더 보수적으로 간 것 — 일부러 문을 좁힌 판단

| | 무엇을 | 왜 좁혔나 |
| --- | --- | --- |
| **역할이 있어도 "모드"를 안 바꾸면 조언가 기능 잠김** | 남의 고민을 보는 일은 **의식적으로 그 역할을 입었을 때만** 일어나야 한다. 실수로 열람하는 일이 없다 |
| **관리자가 자기 권한을 스스로 못 뺌 / 마지막 관리자는 못 뺌** | 관리자가 0명이 되면 **권한을 되돌릴 사람도 없다.** 시스템이 잠긴다 |
| **"살아있는 관리자"만 셈** | 정지된 계정은 로그인이 안 된다. 관리자로 세면 "아직 한 명 남았다"는 판정이 **거짓**이 된다 |
| **초안 상태 조언은 관리자 검수 대기열에 안 올림** | 안 그러면 **쓰다 만 글이 승인**될 수 있다 |
| **고민 삭제는 지우는 게 아니라 숨김** | 사용자 화면에선 사라지지만 조언·배정 이력은 남는다. 분쟁 시 확인할 근거가 필요하다 |
| **역할 부여·회수는 알림을 안 보냄** | "관리자가 당신의 자격을 회수했습니다"는 알림은 맥락 없이 받으면 상처가 된다. 관리자가 직접 소통할 문제로 남겼다 |
| **Django 관리 화면에서 역할·알림 손편집 금지** | 손으로 고치면 강등도 감사 기록도 안 남는다. **가장 빠른 길에 기록이 없으면 감사 기록이 아니다** |
| **자격 회수해도 맡고 있던 고민 배정은 유지** | 한 번의 회수가 배정 해제·상태 변경·알림까지 연쇄하면 **관리자가 무슨 일이 일어났는지 모른다.** 명시적으로 해제하게 했다 |

### 2-3. 설계 의도와 어긋난 것 — **없음**

처음 정한 것 중 바뀐 것은 하나도 없다. 확인한 항목:

- 고민 분류 11종, 조언 상태 5종, 알림 종류 5종 — **전부 그대로**
- "승인된 조언만 사용자에게 보인다" — 6개 화면 전부에서 지켜짐
- 실명·자기평가 신청서 배제 — 유지
- 로그인 방식(세션 쿠키 하나) — 유지
- 44개 API 목록 — 추가도 삭제도 없음

### 2-4. 남은 불일치 2건 (기능 문제 아님, M5에서 정리)

| | 내용 |
| --- | --- |
| **시각 표기** | 문서엔 "한국 시간으로 응답"이라 적혀 있는데 실제로는 세계 표준시(UTC)로 나간다. 화면에서 9시간 차이로 보일 수 있다 |
| **접근 거부 방식 1곳** | 배정 안 된 조언가가 남의 고민 상세를 열면 "권한 없음"이 나온다. 이번에 세운 규칙(api.md §1.8)대로면 "없음"이 맞다 |

## 3. 판정

**이 앱은 설계자가 의도한 그 서비스다.** 44개 API 전부가 처음 정한 경계 안에 있고, 달라진 8건은 **원래 의도를 더 잘 지키기 위한 보강**이며, 좁힌 8건은 전부 **"틀렸을 때의 피해가 큰 쪽"을 막는** 선택이었다.

다만 정직하게: **지금까지 확인한 것은 "코드가 의도대로 동작한다"까지다.** 실제 사용자가 써본 적은 없다. 다음 단계(M5)의 스모크 테스트가 처음부터 끝까지 한 번 통과시켜 보는 확인이다.
